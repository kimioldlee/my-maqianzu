# 任务隔离与中断恢复

## task-id 生命周期

只有明确开始全新新闻任务时生成新的唯一 task-id。续跑、修订、复查、验证器重跑和中断恢复一律沿用原 task-id 与原任务目录。

续跑前只读检查本任务目录：文件是否存在、是否非空、阶段文件是否只有加载提示或等待文字。继续缺失或无效阶段，不重复已经有效完成的预检、检索、事实核验和 Sepia 阶段。

禁止读取其他任务作为本任务工作稿，禁止覆盖、删除或移动其他 task-id、`outputs/` 根目录旧文件或任何非本任务文件。

## 阶段文件与上下文预算

初稿立即写入 `final_draft.md`。后续 Sepia 阶段使用文件路径传递，只把阶段名、输入输出路径、问题清单或修改计划带入上下文，不反复粘贴完整正文。

`sepia-refactor` 覆盖本任务自己的 `final_draft.md`，`sepia_refactor.md` 只保存修改记录。第二次复查只读取修订后的正文，不重新加载初稿或第一次诊断全文。

大型语料、索引和 JSON 一律定点读取。验证器结果只读取必要字段。

## 中断条件

出现 `Autocompact is thrashing`、`context limit`、上下文超限或压缩失败时：

1. 停止加载新的大型文件和发起新检索。
2. 保留本任务目录内所有文件，不删除、不移动、不从头重跑。
3. 输出恢复提示，列出项目根目录、原 task-id、任务目录、用户要求、现存文件状态、已完成阶段、下一阶段、输入输出路径和验证器摘要。
4. 新会话从缺失阶段继续，只传路径和精简字段。

恢复提示模板：

```text
[恢复提示] 项目：madugong-perspective；任务：<用户原始要求>
项目根目录：<完整 PROJECT_ROOT>
task-id：<原 task-id，不得新建>
完整任务目录：<PROJECT_ROOT>/outputs/<task-id>/
已完成阶段：<阶段列表>
下一缺失阶段：<sepia-refactor | 第二次 sepia-review | 终稿验证 | 交付>
禁止重跑：预检 / 检索 / 事实核验 / 已完成的 Sepia 阶段。
现存文件：<逐项标注有效、缺失或无效>
输入路径：<...>；输出路径：<...>
验证器摘要：pass=<...> exitCode=<...> violations=<精简条目>
上下文预算：只传路径与精简字段，不传完整正文、完整 JSON 或全文语料。
```
